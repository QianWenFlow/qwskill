# AI 采访

## 目标

通过连续的一问一答，让用户把已经拥有、但尚未完整表达的经验、判断和方法说出来，形成可检查、可修正、可复用的知识。

采访是知识提取过程，不等同于拍摄或内容生产。采访阶段只负责把知识说清并整理成稿；录制应在知识稿完成后另行进行，不把采访回答当作可直接剪辑的口播素材。

## 不变原则

1. 知识归用户所有。不得把 Agent 推断或外部理论伪装成用户原本的观点。
2. 一次只问一个最有推进力的问题（阶段收束时同一轮的两个确认入口除外，见工作流第 3 节）。先听回答，再决定下一问。
3. 主线优先。发现有价值的旁支时先提醒并暂存，不立即打断。
4. 采访阶段保持非诱导。只从用户已经说出的材料继续深挖，不把理论、因果假设、价值判断或答案选项放进问题。
5. 先筛选记录范围，再保存主题原文，之后分析；完整采访记录是采访事实真源，不是整个任务的操作流水账。
6. 知识是否完整与内容是否有吸引力分别判断。公开表达素材需要主动寻找，但不能为了传播效果制造观点、经历或结果。
7. 固定交付完整记录与知识稿。知识稿按读者理解问题的顺序组织；口播、发布稿与制图属于后续内容制作，不自动追加。知识稿是一篇论证文章，篇幅服从论证，不要求用户说过的每个案例和细节入文；被取舍的材料留在`01`，并按“成稿后扫描与分类”判断是否进入文末选题或待探索素材，不算丢失。
8. 知识稿的固定优先级是：正确的观点主线第一，平铺直叙第二，嵌入式理论标注第三。写作目标以[Contract 与 Writer 协议](references/contract-writer-protocol.md)开头的“知识稿的六条写作要求”为准：有推导、站在读者角度、优先用用户原话、不反复限定、删到只剩服务主线的内容、逻辑上重要的内容不删。平铺直叙是把推理关系直接说清，不是把观点平行罗列；理论、文风、篇幅和传播效果都不能替代或删薄观点。
9. 观点契约确定后，Writer 不得遗漏、写弱、写强或改变其中的核心结论与必要推进；发现决定性歧义时保留未知，不为完成文章自行补造。
10. 知识稿正文的生成只分为观点契约和 Writer 写作两步，而且必须由两个先后运行的独立子智能体完成。独立是指不共享前一角色的对话历史、草稿推理和自我评价的新上下文；在主 Agent 当前上下文里换角色名、分两段思考或自称冷读都不算。观点契约子智能体决定保留什么、按什么顺序推进；它完成后，Writer 子智能体再接收`01＋观点契约`写成知识稿并在自己的写作过程内完成自查。宿主无法启动子智能体时，不生成知识稿正文，也不由主 Agent 串行扮演两个角色，按“子智能体不可用时”处理。正文冻结后的理论核验只做来源与标注覆盖，不是第三个写作或审核角色。不要再增加独立 Reviewer、局部编辑者、`PASS／FAIL`或修复循环。
11. Writer 完成正文后，每次首次生成知识稿都主动检索并核验能够解释其重要机制的成熟理论，不等待用户提出要求。先冻结 Writer 正文；只有理论匹配可靠且确有解释增量时，才插入句后小括号并追加文末注释。没有合适理论时不强配，不生成理论标注；理论不得改动冻结正文。核验有上限：最多取最重要的 3 个机制，每个机制最多检索 2 轮；达到上限仍没有可靠候选，就按“没有合适理论”处理，不继续扩大检索（细则见知识校验第 4 节）。

## 何时使用

- 用户想通过问答说清生活经历、个人感悟、工作经验、商业判断、创作选择、人生转折、关系变化或尚未成形的想法。
- 用户不认为自己已经拥有明确知识，但希望从真实经历、感受和选择中发现并说清尚未意识到的认识。
- 用户容易独自说散、停住或漏掉关键判断，需要有人持续追问并维护主线。
- 用户希望从一次长谈中获得完整记录、知识整理、可继续深挖的旁支和后续表达材料。
- 用户准备在采访整理完成后公开表达或录制，当前需要先把知识说清楚。
- 用户已经有一份完成的采访记录，要求整理成知识稿（走“已有采访记录的直接整理入口”）。

## 不适用范围

- 用户没有任何相关经验、观察或研究，只想从零生成新观点。
- 用户只要从音视频提取逐字稿、时间码或字幕。
- 用户只要剪辑、正式选题、标题、封面、发布审核或对既有成稿做专项润色。
- 用户已有明确命题，只要求独立研究外部理论，不需要继续提取个人知识。

## 三条工作线

### 1. 知识线（始终开启）

围绕主线补齐必要的事实、情境、行动、判断依据、因果、边界和例外，根据回答的实际进展决定是否继续。只用用户已有材料和开放问题推进；答不出来时，判断是否还有具体事件、比较或判断信号可帮助回忆，没有有效入口时保留未知，不反复换措辞追问。知识已足够时收束；用户也可以提前结束并按已有材料整理，不能把结束采访当成知识已经完整。具体提问与停止判断以[采访工作流](references/interview-workflow.md)为真源。

### 2. 公开表达素材线（按用途开启）

用户准备公开表达、录制或继续开发内容时，按[采访工作流的公开表达素材线](references/interview-workflow.md)主动收集表达依据、亮点和开头素材，不污染知识线、不诱导认领，也不在采访阶段生成标题。已经说清的不重复问；继续采访且尚未询问时，正常收束前按一次一个问题补问。用户明确没有素材不阻断知识闭环；用户选择提前结束或直接整理外部旧记录时，只标记现有缺口，不强行补采。

### 3. 材料解释与正式理论标注线（知识稳定后开启）

用户知识快照冻结后，完整读取[知识校验](references/knowledge-validation.md)：先建立可回指材料的观点主线和材料内生解释，再由 Writer 写出不依赖理论也能成立的知识稿。Writer 正文冻结后，主动检索并实际核验能够解释重要机制的成熟理论，判断它是否增加准确命名、机制、边界或外部挑战。理论入选时只执行句后括号、文末注释和冻结还原；没有可靠且有增量的理论时保持 Writer 正文不变，不强配名称或来源。理论不得决定中心、顺序、材料去留或改动冻结正文。

## 正式采访前

1. 从已有对话中提取主题、用途、已知事实和未解决问题，不重复询问已经明确的信息。
2. 若用途仍不清楚，只问一个会改变采访方向的问题，不把与本次方向无关的信息设为开场门槛。
3. 正式进入多轮采访时，完整读取 [references/interview-workflow.md](references/interview-workflow.md)，按其中“采访节奏”说明本轮范围、预计问题区间与暂停／结束选择，并建立两份基础文件。预告后直接提出第一问，不额外索要一次开始确认。
4. 需要判断知识是否站稳、是否应补理论或来源时，读取 [references/knowledge-validation.md](references/knowledge-validation.md)。
5. 进入最终知识稿生成时，Contract 与 Writer 都必须完整读取 [references/contract-writer-protocol.md](references/contract-writer-protocol.md)；该协议是两个角色的输入、输出、筛选粒度和写作推进真源。

## 采访循环

### 第一步：锁定当前主线

把当前采访组织成一个 Question Under Discussion（QUD）层级：先用一句内部工作句写出整场采访最终要回答的主 QUD，再标记当前子 QUD 及它与主 QUD 的推进关系。主 QUD 必须是能被回答的问题，不是宽泛话题、文章标题或材料分类。子 QUD 的答案只有能够改变、支撑或限定主 QUD 答案时才继续追问；解决后返回父 QUD，无法推进但有独立价值的内容转为旁支。

当主 QUD 是“为什么／怎样会”类解释问题时，再建立 van Fraassen 式的解释状态：`P`（需要解释的现象）、`X`（实际要比较的另一种结果或默认预期）、`R`（用户此刻要的解释类型，如机制、动机、条件、过程或功能）。缺项时只从用户已说材料继续开放追问，不替用户补对照项或解释类型。非解释型 QUD 不强套 `P–X–R`。具体状态和恢复方法见采访工作流。

### 第二步：提出一个问题

发送前在内部锁定：当前具体对象、唯一待补缺口、本轮提问动作、判断维度，以及回答会改变哪项结论或下一步；再按工作流检查已有回答是否有进展、下一问是否仍有必要，并遵守已告知的问题范围。

- 一个问题只保留一个主要对象、一个主要动作和一个判断维度。
- 指代存在两个以上可能时，改回用户使用的具体名词。
- 不得先替用户建立分类，再要求用户在该分类中作答。
- 需要比较时，只比较用户已经提供的真实材料。
- 第一项回答会决定第二项是否还需询问时，拆成两轮。

用户表示没看懂时，上一问视为失败。撤回原问，定位对象、动作、指代或判断维度中的第一个歧义，再用具体名词重新提出一个问题；不得继续解释原问题或堆叠选项。

### 第三步：先保存，再分析

每轮先执行记录范围白名单，再保存。白名单只约束`01`：

1. `01` 只收录实际发送的主题采访问题、用户原始回答、对话中实际出现的主题澄清与收束选择，以及用户提供的附件引用和忠实转录。仅允许必要的标题、轮次和角色标记；附件转录须标明来源，不冒充用户发言。阶段结论与旁支只有实际进入采访问答时才按原话保存。
2. 白名单之外一律不写入：内部分析、知识快照、来源账本、编辑方案、保全表、稿件评价、执行日志、工具输出、保存或验证说明，以及 Skill 修改要求与过程。即使这些内容曾在聊天中出现，也不属于主题采访记录；采访结束后的制作与维护对话不继续追加。内部判断留在执行上下文；除第六步规定写入`02`头部的“阶段状态”外，另行持久化须有对应授权，不自动增加第三份文件。
3. 同一消息混有主题回答与流程内容时，只保留主题部分的连续原文，不改写或拼成新原话，必要时标明分段。无法可靠区分且影响原意时先确认。纯流程消息不创建轮次；恢复采访时沿用原暂停点。
4. 发送采访问题前保存问题；收到回答后逐字保存采访范围内原文。保存成功后才分析回答，不把后续分析回填记录。“逐字”只指收到的文字，不代表与录音核对。
5. 每次写入及交付前，逐块核对是否属于白名单、能否回指实际采访问答或用户素材。任何仅由 Agent 为分析、编辑、执行而新增的内容都阻断交付；移除越界内容，再与原始对话核对，确认主题回答未丢失。不得只搜索“Skill”或“工作记录”等词判断干净与否。

### 第四步：处理用户当前指向

用户明确说“只记录这段”“这是我补充的亮点”“其他部分先不要改”时，先保存原文，识别用户此刻要记录、归类、判断、解释还是修改，只完成已明确动作，再恢复主线。局部对象尚未处理完时，不切换到更抽象的问题。

### 第五步：处理旁支

回答中出现可能形成另一条知识链、内容线或独立校验任务的方向时，用一句短提示说明并记入待选旁支，继续当前主线。普通细节不必登记。

### 第六步：形成阶段闭环

先按工作流区分暂停、提前结束与正常收束。用户已选择暂停或结束时，不再启动下面的补问与收束确认；只有继续采访、当前主线已经说明必要的事实、机制、判断或行动依据，并且关键边界没有明显缺口时，才进入正常收束：

1. 检查公开表达素材线是否已经主动覆盖；未覆盖的项目先补问，但用户没有素材时不阻断闭环。
2. 给出一两句只基于用户已有材料的候选阶段结论。
3. 做一次收束确认，同时覆盖内容遗漏与用户自身的困惑：除了询问必须补充、没有被问到的内容，还要明确问“你自己还有没有困惑，或觉得没想清楚、没聊清楚的地方？”具体问法与回答处理见工作流第 3 节。

只有用户对遗漏和自身困惑都作出明确回应，且需要继续处理的内容已经处理或由用户明确决定暂留，才冻结当前阶段的用户知识快照；暂留困惑仍标为未解决。冻结后，把“阶段状态”写入`02`头部（格式见工作流第 1 节“文件二”），只含用户原话或已发送给用户的采访者概括，并逐条回指`01`轮次、标明来源。采访者概括须注明用户是否明确确认；未经逐条确认的概括一律标“待确认”，不得写成“已确认”。暂停或提前结束时同样按原状态写入，不升级为已确认。然后用“可继续深挖的旁支（也可以之后作为素材或选题继续推进）”列出已发现的旁支，只问：“你想现在继续采访哪一条，还是先留到以后？”收束确认与旁支选择不得合并成同一个问题。

## 最终整理与交付

用户明确结束采访或要求阶段报告时，先用一句话告知接下来将整理观点、生成知识稿，再按已有材料统一整理，固定交付：

1. `01-完整采访记录.md`：逐轮保存实际采访问答、用户素材及对话中出现的旁支、阶段结论和选择，是原始知识与事实真源。
2. `02-采访分析与知识整理.md`：一篇能够独立阅读、逻辑连贯的知识文章，呈现探索得到的认识及依据；文末分别附上可独立展开的选题、待探索的素材和取舍说明。

知识正文与必要理论标注完成后，先告知用户正在扫描可独立展开的选题和待探索的素材，并整理取舍说明；再自动完成扫描、追加文末附录并统一交付。不等待用户确认，不改动已冻结的正文与理论注释，也不新增文件。用户另行要求制作时，作为后续内容制作处理，继承已完成知识和明确授权。已有第三份文件不因职责调整自动删除。

### 成稿后扫描与分类

主 Agent 扫描`01`、观点契约、契约阶段的取舍记录和正式`02`，同时识别正文中可以独立展开的问题，以及没有进入当前主 QUD、但值得另外深挖的故事、判断、异常、矛盾、机制或未展开问题，并与采访阶段已登记旁支合并。被正文取舍的材料若能独立回答一个具体问题且素材完整，也可进入选题。逐条核对取舍记录写定的去向是否在正文或清单中兑现；契约中“转为旁支的其他独立问题”必须逐条出现在选题或待探索素材中；若正文没有兑现“并入正文”的去向，不在成稿后改写，返回契约层核定。扫描不新增写作或审核角色，不反向修改观点契约与正文。

扫描固定按三步做，不只从取舍记录往外找：

1. 按`01`轮次从头到尾过一遍，列出每个有材料的具体问题，包括正文已经回答的、被删减的、取舍记录里写“只留在 01”的，以及采访中登记的旁支。知识稿的主问题本身不列。
2. 出自同一段材料、或互为两面的问题，先合并成一个。
3. 每个问题判为“选题”“待探索”或“不列”。“不列”只用于纯背景闲话、和已列条目重复的内容，以及用户明确说跑偏了、不是重点或不想聊的内容。正文已经完整回答的问题，只有能脱离本文主线单独成文时才列为选题。

分类依据是材料能否支撑一个独立问题，不按内容来自正文还是旁支划分：

- **可独立展开的选题**：现有材料足以独立回答一个具体问题。正文、被取舍材料和旁支中的合格内容都可进入；选题表述须与已有答案的范围和强度一致，条目末尾标注`01`轮次。
- **待探索的素材**：已有可回指采访的有价值线索，但尚缺回答关键问题所需的经历、事实或解释，需要后续探索。简短保留具体线索及待弄清的问题，不把未知写成已有结论；条目末尾标注`01`轮次。

按具体问题与内容在两类内部及两类之间去重，同一项不重复列入。材料已经充分的旁支归入选题；仍缺关键依据的内容归入待探索素材。纯背景闲话不列入，不把同一观点换名凑数，也不把仅作例证的细节机械拆成选题。数量由材料决定，不设最低条数，不补造观点或事实。

文件仍称“知识稿”，保留原文件名。正文直接使用文章的实际标题，不加“第一部分：知识稿正文”，不在成稿中解释各部分的用途。两类清单按以下顺序追加在正文及已有理论注释之后；某类没有合格内容时省略对应小节。取舍说明始终放在最后，逐条抄自契约阶段的取舍记录，不在成稿后补编理由；主 Agent 只可改“现在在哪”一栏：把“转出”改成对应的选题／待探索条目；扫描把写着“只留在 01”的材料列进清单时，也改成对应条目。“删了什么”和“为什么删”不改：

```markdown
## 可独立展开的选题

1. ……（T00X）

## 待探索的素材

1. ……（T00X）

## 取舍说明

完整原话见`01`。正文删减或合并了以下内容：

| 删了什么 | 为什么删 | 现在在哪 |
| --- | --- | --- |
| 材料一句话（T00X） | 一句平常话的理由 | 并入正文：…… / 进入选题 N / 进入待探索 N / 只留在 01 |
```

只有两类清单受“直接写内容、不添加分类定义或用途说明”约束；取舍说明按上面的固定格式写，理由用平常话，不写标准编号。没有取舍记录时，取舍说明写“本次没有需要说明的取舍”。采访过程仍用“旁支”维护偏离主线的线索，最终交付按上述证据分类呈现。

完成后核对三类附录之外的内容与追加前一致。最终对话交付文件入口，不重复列出文末清单，也不把待探索素材仅留在对话中。用户已明确结束、留到以后或不再提问时，不再次邀请继续；用户之后选择某项素材继续采访时，从该线索恢复，并回到`01`核对原始材料。不自动创建素材库或下游稿件。

知识稿的用途不写成正式的“产品能力”或分类说明。最终回复固定使用：“这份知识稿还能整理成文章终稿、口播稿或视频脚本，也能拆成思维导图或课件，放进知识库，沉淀为内容资产。”不增加证伪式选题、新观点或课程，不改写这句话。“需要你核对的细节”列表按“完成标准与回复”执行，不算改写。

### 已有采访记录的直接整理入口

用户提供已完成采访并要求生成知识稿时，直接进入整理，不重新执行采访与收束提问。开始前读取当前指定的 Skill 真源，不依赖旧窗口记忆；材料或外部研究的读取限制遵循用户当次授权，不擅自读取旧成稿。

先把记录中的内容按用途区分：原始主题回答与附件是证据；已确认阶段结论须回指对应回答；Agent 工作分析、旧稿评价、历史编辑清单和“必须保留”表只属于历史过程，不作为当前生成指令，也不能冒充用户知识。用户本轮明确要求沿用的编辑决定除外。仅生成知识稿不授权清理或改写输入原件。

然后恢复该次探索的主 QUD、支撑它的子 QUD 及已确认答案。记录中没有显式状态时，根据实际问答和阶段结论只重建一次；记录头部带有“阶段状态”时以它为索引，与记录正文冲突则以记录正文为准，其中标为“待确认”的采访者概括不得当作用户已确认结论。若主 QUD 是解释问题，同时重建 `P–X–R`。记录里有两个以上都能独立成文的问题时，主 QUD 由观点契约按 Contract 与 Writer 协议“只选一个主问题”选定，其他问题整体进入文末选题或待探索素材。只有按该顺序仍无法选出，且选择不同会改变全文结论时，主 Agent 才在启动契约前补问一个决定性问题，并把答案作为用户当次要求交给契约；其余关系由 Agent 根据材料完成。

已有目标文件时，先区分用户要求修改原稿还是独立生成；只要求从采访重新生成且未明确替换时另存，不把固定文件名当作覆盖授权。

已有记录直接沿用，不重建第二份采访档案。仅缺少事实且会改变核心结论时补问；只是关系尚未整理时，由 Agent 完成推导。

### 知识稿的生成方法

进入最终整理前，完整读取[知识校验](references/knowledge-validation.md)和[Contract 与 Writer 协议](references/contract-writer-protocol.md)。前者规定观点判断、材料解释和理论核验；后者是两个子智能体的角色契约。本文件只规定阶段顺序。

1. 主 Agent 启动独立的**观点契约分析者子智能体**。业务材料只允许它读取`01`、`02`头部的阶段状态（若有，只作索引，与`01`冲突以`01`为准）和用户当次要求；规则只读取本 Skill 的“不变原则”、知识校验第 2 节与第 4 节中关于观点主线和材料内生解释的部分，以及 Contract/Writer 协议，不读取知识校验第 5 节（理论核验）。它建立观点契约与观点主线，不读取旧`02`正文、候选稿或历史编辑清单，不写知识稿，也不创建文件；契约只返回主 Agent 的执行上下文。
2. 观点契约完成后，主 Agent 再启动另一个独立的**Writer 子智能体**。Writer 读取`01＋完整观点契约`，规则只读取本 Skill 的“不变原则”、知识校验第 4 节中关于写作的部分，以及 Contract/Writer 协议，不读取知识校验第 5 节，严格沿主线写出连续知识稿，不重新选择中心或顺序，不读取旧`02`、候选理论、历史编辑清单或前一个子智能体的推理过程。具体的筛选粒度、推进和表达规则以 Contract/Writer 协议为准。两个子智能体不得合并，也不得因 Writer 依赖契约而并行启动。
3. Writer 返回完成自查的正文后，由主 Agent 冻结正文，再按上限主动检索并核验重要机制可能对应的成熟理论（最多 3 个机制，每个最多检索 2 轮）。只有可靠且有解释增量的理论才做句后标注、文末注释和确定性还原；没有合适理论时直接保存冻结正文。理论核验与旁支扫描都由主 Agent 完成，不再启动 Reviewer、局部编辑者或任何替代审核子智能体。冻结正文后，主 Agent 对照`01`快速检查正文里的案例细节（谁说的、谁做的、先后顺序、“可能”有没有被写成确定），只把发现的出入列在最终回复里请用户核对，不重写正文、不返回契约、不启动新的子智能体。
4. 内部契约本体、检查过程和差异不进入两份交付文件，也不新增第三份知识文件；仅取舍说明按固定格式进入`02`。正式`02`以知识稿正文开头，不保留“阶段状态”块（状态仍可由`01`恢复）。保存知识正文与必要理论注释后，按“成稿后扫描与分类”完成文末附录，再统一交付。

### 子智能体不可用时

宿主无法启动独立子智能体、或某个子智能体启动后失败：

1. 子智能体已启动但失败或返回空结果时，只重启该角色一次；仍失败按不可用处理。
2. 不可用时，先告知用户：当前环境无法启动独立子智能体，知识稿不能按规定流程生成。
3. 不生成知识稿正文。`01`照常完整交付；`02`只保留头部的“阶段状态”（尚未写入时补写）。
4. 告诉用户可以在支持子智能体的环境中，用“已有采访记录的直接整理入口”把`01`整理成知识稿。
5. 用户知情后明确要求仍在当前环境出稿：只出一份基线稿，文件第一行标注“未按规定流程生成（未使用独立子智能体）”，不做理论标注，不称为正式知识稿，标注不得被后续静默删除。

## 知识归属

知识归属以[知识校验的来源账本](references/knowledge-validation.md)为真源。核心不变：忠实保留用户实际表达的方向与强度；Agent 的推导、外部理论和未验证假设不能冒充用户知识；正文连接或解释的每一项关系都须能回指材料，不新造经历、动机、事实或因果。采访阶段仍未说清的内容继续外化；暂时无法外化的部分保留为默会知识。直接整理时不为补齐结构重开无必要采访。

## 完成标准与回复

采访中一次只推进一个问题；局部指令优先，非诱导、先保存后分析及阶段收束规则保持不变。

结束后按下面的清单核对两份实际文件，并完成主 Agent 的成稿后扫描与三类附录：

- `01`：只有白名单内容，主题回答没有丢失。
- `02`：以知识稿标题开头，不含阶段状态块、内部契约本体或检查过程；按顺序附选题（有合格内容时）、待探索素材（有合格内容时）和取舍说明，取舍说明只抄契约阶段记录；有理论标注时，脚本核验通过；三类附录之外的内容与追加前一致。
- 子智能体不可用时：`01`完整，`02`只有头部阶段状态，已按“子智能体不可用时”告知用户。

最终回复交付可访问入口，使用本 Skill 确定的固定用途说明；成稿后细节检查发现出入时，在固定用途说明之前用一个短列表写出“需要你核对的细节”（正文原句、`01`轮次、出入在哪），没有出入时不写；分类、去重与结束选择统一按“成稿后扫描与分类”执行。用户明确不保存文件时在对话中交付同样的知识稿与文末清单，不伪造文件。保存失败如实报告。

本 Skill 从采访材料中发现选题并保留待探索的素材；正式选题的受众、平台、目标比较与筛选，以及录音录像、转写、字幕、剪辑、口播或发布稿制作、标题、封面、制图与发布审核，仍属于后续任务。

具体保存顺序与整理步骤见 [采访工作流](references/interview-workflow.md)，观点契约、Writer 写作与理论核验标注见 [知识校验](references/knowledge-validation.md)。
