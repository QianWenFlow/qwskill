# 文字修改的落地方法

适用：修改句子、段落、指代和措辞。深度升维判断出问题位置后，按本文件决定怎么改。

## 层级

文字任务的层级是：词 → 句 → 段（前后句衔接）→ 全文论证结构 → 写作意图与读者。检查时从出问题的词句往上看，到能解释问题的那一层为止。

## 指代不明怎么改

升维常能判断出「不必换词，在前面补一句先行句」，但补在哪、补什么最容易失手。

先锁定范围：用户已定稿或明确要保留的句子不动；原词（如「这」）默认保留，优先让它通过上下文变清楚。

再比较三种改法，选能解决问题的最小改动：

1. **换词**：把「这」换成名词短语。适合被指代对象就在上一句、只是有两个候选。
2. **补先行句**：在「这」之前补一句，点名被指代对象。适合对象在前文分散出现、读者需要先被收拢。
3. **调整结构**：调换句序、合并两句或拆句。适合指代不明是句序问题造成的。

选择补先行句时，先比较位置：列出从「被指代对象最后一次出现」到「这」所在句之间的每个句间位置，逐个设想补在那里，选读起来最自然、对后文改动最少的一处，并说明为什么不选其他位置。插入后不能拆开原文已有的转折或对比句对（例如「虽然……但是……」「一方面……另一方面……」）。

补的这句话要同时满足：

- **点名**：用名词短语明确说出「这」要指的对象，让它成为离「这」最近、最显眼的候选；
- **接上前文**：与上一句的逻辑关系一致（承接、总结、转折或因果），不是孤立的总结句；
- **不加料**：不引入新论点、新信息，也不重复前文已经说过的话；
- **贴原文**：长度、语气与相邻句子一致，不破坏原文已有的对比和节奏，通常一句、不长于相邻句；
- **为后文服务**：补完后，「这」所在句不需要再改就成立。

验收：先单独读「补句＋这句」，再放回整段读；问「这指什么」，只能有一个答案，且正好是作者原意。若还要连带改「这」所在句才通顺，说明位置或改法选错，回到上面重新比较。
