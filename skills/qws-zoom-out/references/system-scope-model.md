# 系统边界与问题重定义

## 一、校准问题、目标和前提

先恢复当前事实、有效决定和用户真正关心的结果，区分：眼前怎么问、希望理解或改变什么、当前方案凭什么有效。既检查用户说法，也检查 Agent 已形成的解释。

- **目标与手段**：根据已有材料检查当前目标达成后为了得到什么，辨别最终诉求、阶段目标、指标和手段。阶段目标不因存在长期目标而自动失效；检查它们之间是否有真实连接。
- **规则与前提**：当前判断默认了哪些因果关系、评价标准、选项或职责？这些是事实、已确认的偏好，还是尚未验证的假设？这一步同时承担双环学习的检查，不再单独跑一轮同义流程。
- **反例与遗漏**：哪些已有事实无法被解释？即使当前方案完全成功，原来的疑问或目标是否仍未解决？如果暂不采用眼前方案，是否还有其他解释或实现途径？

可以提出修正目标：说明旧目标为何不能代表真实诉求，以及改后怎样影响方案和验收。事实可以推翻错误前提，却不能替用户决定价值偏好；存在多个有效但冲突的诉求时，只确认决定后续路径的关键取舍。尚未确定时保留条件分支，不偷偷换掉优化对象。

## 二、选择检查路径

原框架成立且没有影响结论的缺口时，保留它。需要改变时，根据缺口选择下列路径，可以结合使用。

### 常见打转成因

先对照下表认出这次属于哪一类打转。表中是常见类型，不是全部。对不上时不硬套，但仍要判断并说出这是哪一种打转：用一句话概括它的成因，并按表中同样的四项写清信号、往哪里改、可搜索的关键词；再检查这类问题在别的领域是否已有人系统研究过。新出现的类型只在本次回复里说明，不自行改写本表。

| 打转成因 | 信号 | 往哪里改 | 可搜索的关键词 |
| --- | --- | --- | --- |
| 换说法不换前提 | 几次修改动的都是同一个位置，或都默认同一个前提 | 找出共同前提并换掉；或回到打转前的 A | 隐含前提、问题框定、双环学习 |
| 没有固定的评价标准 | 结论跟着最新一句反馈摇摆 | 先定评价标准，再逐项对照 | 评价标准、决策准则、评分量表 |
| 某部分承担了不属于它的任务 | 这一部分怎么改都不对 | 重新分配各部分的职责 | 职责分离、信息层级 |
| 修补不收敛 | 补丁越加越多、互相冲突，结果不变好 | 见下文「修补不收敛」 | 规则膨胀、系统重构、杠杆点 |
| 目标被替换 | 结果符合某个指标或标签，却不是用户要的 | 区分真实目标和代理指标、入口和中心 | 古德哈特定律、代理指标、目标置换 |
| 把症状当原因 | 修的是问题出现的地方，不是问题产生的地方 | 往前找产生问题的环节 | 根因分析、5 Whys |

### 扩大系统范围：遗漏了关系或约束

确定本轮关注的系统对象：为解释或改善当前结果，必须纳入哪些元素、关系、反馈和环境。同地点、同部门或同话题不构成纳入理由。

| 扫描方向 | 检查内容 |
| --- | --- |
| 向上 | 父级流程、系统与最终结果怎样约束当前对象？ |
| 向下 | 哪些子环节、判断或动作共同产生当前结果？ |
| 向前后 | 前置条件、直接产物、下游行动和反馈怎样连接？ |
| 跨时间 | 单次成功、当前阶段与长期积累是否冲突？ |
| 跨角色 | 谁提供输入、掌握决定权、承担后果或缺少信息？ |

文字、内容与账号任务的层级和落地方法，见对应的落地文件。责任层、角色等字段在这些任务中不适用时写「不涉及」，不硬套组织系统。

根据交互强度、反馈强度、时间效应和重复失败，判断局部问题是否由系统关系持续产生。交互弱、后果可逆、验收独立且不影响整体目标时，局部处理通常足够。

需要向上检查时，在同一次调用中完成递归：从直接父级开始，每纳入一层都记录它具体改变的解释、目标、原因、方案、风险、责任层或验收，再检查其父级；遇到没有增益或证据不足的层级，记录首个未纳入层及理由后停止。不能只找到第一个有用的上层就结束，也不能为填满层级而补造系统。

### 修补不收敛：问题在结构，不在缺一条规则

修一个系统（规则集、流程、工具、团队分工）时，出现下列情况中的任意两项，停止继续加补丁：

- 修补次数在增加，规模越来越大；
- 新补丁开始和旧规则冲突；
- 同一类错误换个样子又出现；
- 每次修完，结果质量没有提升。

这时依次检查四件事，找到第一处有问题的就从那里改：

1. **职责分层**：每一部分负责什么是否清楚，有没有把不同职责挤在一处；
2. **交接顺序**：前一步交给后一步的东西和时机是否对；
3. **验收标准**：有没有一个可以对照的好结果或判断标准，来确认改完是否真的变好；
4. **目标**：系统要达成的结果本身是否定对。

原本要加的补丁，如果仍有价值，放进对应的层里（例如改成验收标准中的一项），不再单独追加。

### 重新定义问题：当前说法限制了理解或选项

暂时放下已有方案，保留事实、用户诉求和有效约束，检查是否存在下列有证据的情形：把现象当原因、把手段当目标、把不同职责挤进一个对象、把可组合的办法设成二选一，或用未经验证的标准评价结果。

据此形成值得比较的新问题定义，明确：原来把什么当成了什么，新定义改变了哪项关系，以及它如何解释旧框架遗漏的事实或打开新的解法。换框架可以在同一层发生，不必先找到更大的系统。

其他领域可以提供候选解释或方法，但跨领域必须对应机制：原问题中的对象、关系、约束与反馈，对应到该领域的什么；关键相同点是什么，哪项差异会使借鉴失效。只因名称相似、比喻漂亮或理论层级更高，不足以采纳。没有可靠对应关系时，不强行跨领域。

判断出问题属于哪一类以后（例如修补不收敛、指标与目标冲突、多方共同决定），检查这类问题在别的领域有没有成熟做法：

- **有把握**：直接说出做法，以及它和当前问题的机制怎样对应、在哪里可能不适用；
- **没把握**：不硬套，但至少用一句话点明这是哪一类问题，并给出可以拿去搜索的关键词，提醒用户这类问题很可能已有人系统研究过，可以查对应的理论和做法，再判断能不能迁移。

很多人跳不出局部，是因为不知道这类问题已经有成熟做法。点明问题类型本身就是升维结果的一部分。

## 三、对照原框架比较候选

保留原框架、检查前仍成立的答案作为基线，也保留用户已提出且仍合理的方案。只比较有事实依据、可能改变结论的候选，不机械凑数。框架或分析范围改变，不自动证明新答案更好。

先检查候选是否仍回答同一个真实关切。候选若改变了讨论对象或需要回答的问题，须说明这种改变为何是回应原诉求的必要条件；没有依据时属于换题，不能冒充升维。确需调整目标的候选，先按第一步说明调整依据和取舍，再比较，不能靠更换成功标准显得胜出。

按任务性质判断收益：

- **理解与解释**：能否解释更多相关事实、处理反例、区分竞争解释，并指出什么证据会推翻它；不能用听起来有道理代替证据，也不强制落到行动或收益最大化。
- **选择与行动**：是否更能推进有效目标，补齐从现状到结果的必要环节；比较成本、风险、可行性、权限和验收，检查是否把负担转移给其他环节。

行动任务同时考虑局部修复、系统修复和组合修复。分析需要覆盖整个系统，不代表当前对象必须承担全部工作；根据原因与决定权分配责任，区分本轮处理、需要交接和只作为约束的部分。

选定前，暂时放下候选结论，用原始事实与真实诉求反查：有没有被候选排除但仍成立的解释？生成与检查是否共享了同一个未验证前提？发现足以改变判断的反例，回到问题校准；否则不为再检查而制造新框架。

最后对照原答案与候选答案：在同一真实诉求下，候选是否解释了更多关键事实、解决了原答案未解决的障碍，且没有丢失原答案仍成立的部分？没有净改善时保留原答案，说明检查带来的有效约束即可；原答案被新事实推翻时应修正，不能借回退保留错误答案。

## 四、返回原问题并停止

交回原任务前说清三件事：原先哪项判断应保留或改变，依据是什么；具体改法或候选（按主文件「交回原任务」的规则）；还需要用户决定的那一项。解释任务可以止于更准确的理解；行动任务给出改法与约束，不在本 Skill 内代做完整业务产物。

以下情况停止对应方向的扩展：

- 再往上会改变原命题、原问题，或用户已经确定的定位、目标、价值取舍：这一层是本次的最高层，更上一层只写成约束或待用户决定的事项；
- 继续扩大边界或更换框架，已不改变解释、目标、原因、方案、风险、责任层或验收；
- 新内容只增加背景或抽象程度，无法改变原问题的判断；
- 继续推演依赖未经支持的假设：保留未知，决定性缺口只问当前最关键的一项；
- 更高层影响已经识别，但本轮权限或范围只能把它作为约束、风险或交接事项，不把它变成本轮交付。

停止时记录选择依据和未知，不宣称找到了永远正确的最高层。后续沿用主文件的状态继承与失效规则；重复调用本身不是继续扩展的理由，复核发现实质遗漏也不受旧停止结论束缚。

## 五、方法依据与适用边界

理论用于支持上述判断动作，不用于证明 Skill 已有效；实际表现仍需行为验证。

- **Donald Schön，问题设定与反思性实践**：支持第二、三步重新检查框架，并让事实反馈检验新框架；不意味着换一种说法就算进步。参见 *The Reflective Practitioner*，尤其 “The Structure of Reflection-in-Action”。[MIT 反思性实践课程书目](https://ocw.mit.edu/courses/11-965-reflective-practice-an-approach-for-expanding-your-learning-frontiers-january-iap-2007/pages/readings/)。
- **Ralph Keeney，价值导向思考**：支持区分目的与手段、从有效目标生成和比较方案；主要用于选择与行动，不能用偏好代替解释任务的事实证据。[Applying Value-Focused Thinking](https://scholars.duke.edu/publication/780161)。
- **Chris Argyris，双环学习**：并入第一步，检查支配行动的目标、规则和前提，不另设重复环节。[Double Loop Learning in Organizations](https://hbr.org/1977/09/double-loop-learning-in-organizations)。
- **Donella Meadows，系统杠杆点**：帮助识别目标、规则、信息流与反馈等介入位置；不默认越高层越适合当前任务。[Leverage Points](https://donellameadows.org/archives/leverage-points-places-to-intervene-in-a-system/)。
- **Horst Rittel 与 Melvin Webber，棘手问题**：问题定义与解法互相影响，当前问题可能是另一问题的症状；用于检验定义，不把所有任务判成无边界的复杂问题。[Dilemmas in a General Theory of Planning](https://doi.org/10.1007/BF01405730)。
- **Herbert Simon，近似可分解系统**：交互较弱时局部处理可以成立，支持保留原框架与停止扩展。[The Architecture of Complexity](https://www.andrew.cmu.edu/course/15-440/assets/READINGS/simon-architecture-of-complexity-1962.pdf)。
- **Maxwell McCombs 与 Donald Shaw，议程设置**：媒体反复强调什么、从什么角度讲，影响受众认为什么重要、怎样理解它；用于内容与账号任务的议程检查，不作为每条内容都要讲理论的理由。[The Agenda-Setting Function of Mass Media](https://doi.org/10.1086/267990)。
- **NASA 系统工程手册**：支持父级需求追溯、接口检查和整体目标验收；用于系统范围路径，不作为一切问题都必须逐层上移的理由。[NASA Systems Engineering Handbook](https://www.nasa.gov/wp-content/uploads/2018/09/nasa_systems_engineering_handbook_0.pdf)。
